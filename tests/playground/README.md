## Запуск

1. Скопируйте `wp-olympiad-design` в папку, которую монтирует Playground (`/wordpress/wp-content/plugins/`).
2. Поднимите сервер WordPress:
   ```bash
   npx @wp-playground/cli@3.1.59 server --auto-mount=<папка_с_WordPress> \
     --blueprint=tests/playground/blueprint.json --blueprint-may-read-adjacent-files --port=9400
   ```
   `blueprint.json` задаёт `preferredVersions.php` (например, `7.4`) и активирует плагин.
3. Скопируйте `wpd-test-a.php`, `wpd-test-c.php`, `wpd-set.php` в корень WordPress и выполните:
   ```bash
   curl -sL http://127.0.0.1:9400/wpd-test-a.php > resA.txt   # фаза A, выводит строку IDS
   WPD_BASE=http://127.0.0.1:9400 bash phaseB.sh               # фаза B, читает resA.txt из текущей папки
   curl -sL http://127.0.0.1:9400/wpd-test-c.php               # фаза C, последней: удаляет данные плагина
   ```

Важно: Playground хранит базу SQLite в `<папка_с_WordPress>/wp-content/database/`.
Чтобы начать с чистой базы, остановите сервер и удалите файлы `.ht.*` в этой папке.
Фаза C удаляет настройки и мета-поля плагина, поэтому запускайте её последней. `wpd-measure.php` сам создаёт опцию перед замером, потому что фильтр `option_*` не срабатывает для отсутствующей опции.

   Фазы 1.3.0 (после фазы B, до фазы C; `wpd-test-d.php` тоже скопируйте в корень WordPress):
   ```bash
   curl -sL http://127.0.0.1:9400/wpd-test-d.php > resD.txt   # фаза D, выводит строку IDS
   WPD_BASE=http://127.0.0.1:9400 bash phaseE.sh               # фаза E, читает resD.txt
   WPD_BASE=http://127.0.0.1:9400 python3 wpd-browser-test.py ./shots   # фаза F, нужен pip-пакет playwright и Chromium
   ```
   Фазы 1.4.0 (после фазы E, до фазы F; `wpd-test-g.php` скопируйте в корень WordPress):
   ```bash
   curl -sL http://127.0.0.1:9400/wpd-test-g.php > resG1.txt  # фаза G, PHP
   WPD_BASE=http://127.0.0.1:9400 bash phaseG.sh               # фаза G, HTTP; в конце сбрасывает опцию
   ```
   Фазы 1.5.0 (после фазы G, до фазы F; `wpd-test-h.php` и `wpd-h-page.php` скопируйте в корень WordPress):
   ```bash
   curl -sL http://127.0.0.1:9400/wpd-test-h.php > resH1.txt  # фаза H, PHP; в конце удаляет свои записи и опцию
   WPD_BASE=http://127.0.0.1:9400 bash phaseH.sh               # фаза H, HTTP; сохраняет h_components.html
   WPD_BASE=http://127.0.0.1:9400 python3 wpd-browser-test-h.py ./shots   # фаза H, браузер
   ```
   `wpd-h-page.php` — служебный хелпер: создаёт страницы с компонентами (`?plain=1`, `?blocks=1`, с таймером — `?countdown=1`, с главным блоком и карточками — `?hero=1`) и удаляет их (`?cleanup=1`).
   Фазы 1.6.0–1.7.0 (после фазы H, до фазы F; `wpd-test-i.php` и `wpd-test-k.php` скопируйте в корень WordPress):
   ```bash

   WPD_BASE=http://127.0.0.1:9400 bash phaseI.sh               # фаза I, HTTP; в конце сбрасывает опцию
   curl -sL http://127.0.0.1:9400/wpd-test-k.php > resK1.txt  # фаза K, PHP; в конце удаляет опцию
   WPD_BASE=http://127.0.0.1:9400 bash phaseK.sh               # фаза K, HTTP; в конце сбрасывает опцию
   ```
   Фазы 1.8.0 (после фазы K, до фазы F; `wpd-test-l.php` скопируйте в корень WordPress):
   ```bash
   curl -sL http://127.0.0.1:9400/wpd-test-l.php > resL1.txt  # фаза L, PHP; в конце удаляет опцию

   ```
   Браузерную фазу H запускайте на отдельной чистой базе. На чистой базе WordPress иногда показывает окно стартовых
   паттернов, хотя оно отключено в настройках пользователя; обе браузерные фазы закрывают его автоматически.
   Chromium в песочнице с малым объёмом памяти запускается с `--disable-dev-shm-usage`. Если `/tmp` — это tmpfs,
   следите за свободной памятью: при её нехватке страница падает с «Target crashed». Не держите `node_modules` Playground CLI
   в tmpfs: около 0,6 ГБ памяти, и фаза F падает на сохранении страницы с панелью.

   `wpd-test-g.php` вызывает `WPD_Settings::register()`: санитизация опции регистрируется только на `admin_init`,
   а без неё `update_option` из фронтового скрипта сохранил бы значения как есть.

   Фаза F отключает приветственный гид и окно выбора паттерна через REST: записывает
   `persisted_preferences` пользователя (`/wp/v2/users/me`) и перезагружает редактор. На чистой базе это надёжнее,
   чем закрывать окна кликами. На случай, если окно всё же появится, остаётся обработчик, который его закрывает.
   Затем фаза раскрывает область Meta Boxes.
   Скриншоты сайта после фазы F лежат в `screenshots/`, там же скриншоты страницы настроек (`settings-design.png` с палитрами, `settings-stats.png`, `settings-slider.png`, `settings-buttons.png`), главной страницы из компонентов 1.5.0 (`front-components.png`, `front-components-mobile.png`) и блоков в редакторе (`editor-components.png`), три этапа таймера 1.6.0 (`front-countdown.png`) и его настройки (`settings-countdown.png`), контакты с названием организации 1.7.0 (`front-contacts.png`, `settings-contacts.png`), варианты главного блока 1.8.0 (`front-hero-variants.png`), вид «таблетки, контур, Georgia, без теней» (`front-look.png`) и настройки 1.8.0 (`settings-look.png`, `settings-hero.png`).

4. Проверка JavaScript (нужен Node.js). Берётся HTML страницы с включёнными функциями (`f_features.html`, его сохраняет фаза B) и `wpd.js`:
   ```bash
   mkdir -p /tmp/jsdom && cd /tmp/jsdom && npm install jsdom@24
   cp /home/user/wp-design/tests/playground/wpd-js-test.cjs .
   node wpd-js-test.cjs /tmp/pg/f_features.html /home/user/wp-design/wp-olympiad-design/assets/js/wpd.js /tmp/pg/h_components.html
   ```
   Третий аргумент (страница с компонентами из фазы H) включает проверки слайдера и карусели новостей. Раскладки в jsdom нет,
   поэтому ширины ленты и слайдов, `scrollLeft` и `scrollTo` подменяются заглушками.

Фаза B опирается на состояние базы, которое оставляет фаза A (тестовые страницы, FAQ `Q?`, блоки), поэтому всегда начинайте с чистой базы.

`wpd-set.php` — служебный хелпер: меняет опцию плагина по GET-параметру `json`. Только для песочницы, в продакшен не копируйте. WordPress экранирует `$_GET` (`wp_magic_quotes`), поэтому в хелпере нужен `stripslashes()`. Без него JSON не разбирается.
